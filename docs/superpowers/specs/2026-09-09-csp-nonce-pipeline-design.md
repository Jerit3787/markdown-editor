# CSP nonce pipeline — design

**Status:** approved approach (brainstorm 2026-09-09), design under review
**Follows:** `docs/superpowers/specs/2026-09-09-content-security-policy-design.md` (shipped v1.60.2, PR #198). That spec listed "a nonce-per-response pipeline" as a non-goal; this spec removes that deferral.
**Ships as:** a patch release (`1.60.3`) — no user-visible behaviour change. `CHANGELOG.md` `### Changed`, **no** What's New entry, no screenshot (per `CLAUDE.md`'s patch rule).

## Goal

Deliver the Content-Security-Policy as a per-request **`nonce`** carried on a real `Content-Security-Policy` **response header**, generated by the Worker, so that Cloudflare's edge-injected JavaScript Detections (JSD) script stops violating the policy — while keeping every current directive, every current feature, and the existing local test coverage intact.

## Why

v1.60.2 shipped a static CSP via `<meta http-equiv>` in `client/index.html`, duplicated into `client/public/_headers`, with the app's one inline script allowed by its `sha256` hash. In production two edge-injected scripts violated it:

1. **Cloudflare Real User Monitoring (RUM) / Web Analytics** — resolved by disabling RUM injection in the Cloudflare dashboard (Web Analytics → Manage site → *Disable*). Done, verified: no more `static.cloudflareinsights.com/beacon.min.js`.
2. **Cloudflare JavaScript Detections (JSD)** — an inline bootstrap for `/cdn-cgi/challenge-platform/scripts/jsd/main.js`, injected into every HTML response. Its body carries a per-request ray ID and timestamp, so its hash rotates on every page load and cannot be pinned.

Per Cloudflare's own documentation
(`developers.cloudflare.com/cloudflare-challenges/challenge-types/javascript-detections/`):

- JSD is auto-enabled by **Bot Fight Mode** and cannot be disabled on its own while BFM is on.
- *"If your CSP uses a `nonce` for script tags, Cloudflare will add these nonces to the scripts it injects by parsing your CSP response header."*
- *"JavaScript Detections is not supported with `nonce` set via `<meta>` tags."*

So the only CSP-compatible path that keeps JSD working is: a nonce, on a response **header**, set by the Worker per request.

## Non-goals / deferred

- **A violation-reporting endpoint** (`report-uri` / `report-to`). Unchanged from the v1.60.2 spec — still deferred, no log sink, nobody would watch it.
- **Trusted Types.** Unchanged — a separate, larger hardening step.
- **`'strict-dynamic'`.** The host allowlist (`challenges.cloudflare.com`, `www.googletagmanager.com`, the GA `connect-src` wildcards) is retained as-is. `'strict-dynamic'` would make supporting browsers ignore those host sources, forcing GA/Turnstile to load only via nonce-propagation — a real behaviour change and regression risk for no benefit here. The nonce is added *alongside* the allowlist, purely to satisfy JSD.
- **Moving the `local` Playwright project to `wrangler dev`.** Out of scope — too invasive. The `local` suite keeps running against `vite dev` under the `<meta>` policy (see Part 3).
- **CSP on `/api/*` and Durable Object responses.** Unchanged — those render no document.
- **Removing Bot Fight Mode.** The user chose to keep BFM and make the CSP compatible with it, rather than turn it off.
- **A CSP on non-HTML assets** (`.js`, `.css`, fonts). A CSP there does nothing; the `_headers` CSP line is dropped, not moved.

## Global constraints

- Two `tsconfig.json`s, checked separately. `src/**` and `tests/src/**` are full strict — `src/csp.ts` and its test live there.
- The `local` Playwright project (200+ tests) runs against **`vite dev`**, which executes no Worker and processes no `_headers`. Its CSP coverage must survive this change.
- `npm run format` (Prettier) + `npm run typecheck` must pass. `client/public/_headers` is already in `.prettierignore`.
- `client/public/*` is copied verbatim into `client/dist/` by Vite; Cloudflare Workers Assets and `wrangler dev` read `client/dist/_headers`.
- `/privacy` and `/terms` are generated from `legal/*.html` by `scripts/generate-legal.mjs`; the generated files are git-ignored, the templates are the source of truth.
- `wrangler.jsonc` already sets `assets.run_worker_first: true`, so `src/worker.ts`'s `fetch()` runs before the asset layer on every request — the Worker can transform asset responses.
- The app's built HTML shell (`client/dist/index.html`) contains exactly two `<script>` tags: the Vite entry bundle (`<script type="module" crossorigin src="/assets/index-<hash>.js">`) and one attribute-less inline snippet (the mobile-sidebar collapse). The legal pages contain zero `<script>` tags.

## Part 1 — `src/csp.ts` (new module)

A pure, dependency-free module. No I/O, no `env`, fully unit-testable.

```ts
// Per-request Content-Security-Policy for HTML responses.
//
// Delivered as a real response header (not <meta>) carrying a fresh
// `nonce` per request, so Cloudflare's edge-injected JavaScript
// Detections script — whose inline body rotates every request and
// cannot be hash-pinned — is stamped with the same nonce by
// Cloudflare's CSP-header parser and runs without a violation.
//
// client/index.html and legal/*.html keep their own static <meta> CSP
// as the policy enforced under `vite dev` (which runs no Worker). In
// production the Worker strips that <meta> and sets the header below.

/** A fresh CSP nonce: 16 random bytes, standard base64 (~24 chars). */
export function generateNonce(): string {
  const bytes = new Uint8Array(16);
  crypto.getRandomValues(bytes);
  return btoa(String.fromCharCode(...bytes));
}

/** The app-shell policy. Identical to the v1.60.2 <meta> policy except
 *  `script-src` swaps the inline-script hash for the per-request nonce. */
export function appCsp(nonce: string): string {
  return [
    "default-src 'self'",
    "base-uri 'self'",
    "object-src 'none'",
    `script-src 'self' 'nonce-${nonce}' https://challenges.cloudflare.com https://www.googletagmanager.com`,
    "style-src 'self' 'unsafe-inline'",
    "img-src 'self' data: blob: https:",
    "font-src 'self' data:",
    "connect-src 'self' https://challenges.cloudflare.com https://www.googletagmanager.com https://*.google-analytics.com https://*.analytics.google.com",
    "frame-src https://challenges.cloudflare.com",
    "worker-src 'self' blob:",
    "manifest-src 'self'",
    "form-action 'self'",
  ].join("; ");
}

/** The /privacy and /terms policy. The pages ship zero script; the
 *  `script-src 'nonce-…'` exists ONLY so Cloudflare's injected JSD
 *  inline script is stamped and runs cleanly. */
export function legalCsp(nonce: string): string {
  return [
    "default-src 'none'",
    `script-src 'nonce-${nonce}'`,
    "style-src 'unsafe-inline'",
    "img-src 'self'",
    "font-src 'self'",
    "base-uri 'self'",
    "form-action 'none'",
  ].join("; ");
}
```

Notes:

- `btoa(String.fromCharCode(...bytes))` is safe in a Worker (`btoa` is global). 16 bytes → 24 base64 chars including one `=` pad — well within the CSP `nonce-<base64-value>` grammar and the ≥128 bits of entropy the CSP spec recommends.
- `appCsp` drops the `sha256-…` hash entirely. In production the inline sidebar script runs because the Worker adds `nonce="<nonce>"` to it (Part 2). The hash only ever mattered for the `<meta>` policy, which the Worker removes.
- `legalCsp` keeps `default-src 'none'` — the strict standalone policy from v1.60.2 — and adds just `script-src 'nonce-…'`.

## Part 2 — The Worker HTML transform (`src/worker.ts`)

The final line of `fetch()` today is:

```ts
    return env.ASSETS.fetch(request);
```

It becomes (same position, end of `fetch()`, after all `/api/*` routing):

```ts
    const assetRes = await env.ASSETS.fetch(request);
    const contentType = assetRes.headers.get("content-type") ?? "";
    if (!contentType.includes("text/html")) return assetRes;

    const nonce = generateNonce();
    const isLegalPage = url.pathname === "/privacy" || url.pathname === "/terms";
    const policy = isLegalPage ? legalCsp(nonce) : appCsp(nonce);

    const rewritten = new HTMLRewriter()
      .on('meta[http-equiv="Content-Security-Policy"]', { element: (el) => el.remove() })
      .on("script", { element: (el) => el.setAttribute("nonce", nonce) })
      .transform(assetRes);

    const headers = new Headers(rewritten.headers);
    headers.set("Content-Security-Policy", policy);
    headers.set("Cache-Control", "no-store");
    return new Response(rewritten.body, {
      status: rewritten.status,
      statusText: rewritten.statusText,
      headers,
    });
```

Add to the import block at the top of `src/worker.ts`:

```ts
import { generateNonce, appCsp, legalCsp } from "./csp.js";
```

Behaviour:

- **Only `text/html` responses are transformed.** Everything else (`/assets/*.js`, CSS, fonts, images, `site.webmanifest`, `robots.txt`) returns byte-for-byte unchanged, keeping its long-lived cache headers.
- **The `<meta http-equiv="Content-Security-Policy">` element is removed** from the served HTML. The exact selector `meta[http-equiv="Content-Security-Policy"]` matches the attribute value as written in both `client/index.html` and `legal/*.html` (we control both). No case-insensitive flag needed.
- **Every `<script>` gets `nonce="<nonce>"`** — the entry bundle and the inline snippet in the shell; nothing in the legal pages (the handler is a no-op when there are no `<script>` tags).
- **The header CSP replaces `_headers`' CSP** for HTML. The five companion headers set by `_headers` (`X-Frame-Options`, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`, `Cross-Origin-Opener-Policy`) are already on `assetRes` and are preserved by `new Headers(rewritten.headers)`.
- **`Cache-Control: no-store` on the HTML shell only.** A cached HTML document carries a fixed nonce; a later request whose JSD injection uses a *different* nonce would then be blocked. `no-store` on the small shell document guarantees the nonce in the body, the header, and the edge-injected JSD script always agree. Hashed `/assets/*` bundles are untouched and keep caching normally.
- **The SPA fallback** (`not_found_handling: single-page-application` → `index.html` for `/d/<id>`, `/d/<id>/edit`, etc.) returns `text/html` 200 and flows through the same transform — correct, those pages need the shell policy.
- **`HTMLRewriter` streams**; the shell is never fully buffered.

### Where JSD fits

JSD injection happens at Cloudflare's edge, on the response's way out — *after* the Worker. Cloudflare parses the `Content-Security-Policy` response header the Worker set, finds `'nonce-<nonce>'` in `script-src`, and stamps that nonce onto the `<script>` tags it injects. The nonce the Worker put in the header, in the shell's `<script>` tags, and on JSD's injected scripts are then all the same value — no violation.

This is the documented supported configuration. It cannot be exercised under `wrangler dev` or `vite dev` (JSD is not part of either); Part 5 covers post-deploy verification.

## Part 3 — `client/index.html` and `legal/*.html` — unchanged

Both keep their existing `<meta http-equiv="Content-Security-Policy">` exactly as shipped in v1.60.2:

- `client/index.html` — the hash-based shell policy (`script-src … 'sha256-dvrkhVN+dXykZmzU3pQRkYg38F+aYnJ2WXnZwjPgC04=' …`).
- `legal/privacy.html`, `legal/terms.html` — the strict `default-src 'none'; style-src 'unsafe-inline'; img-src 'self'; font-src 'self'; base-uri 'self'; form-action 'none'`.

This `<meta>` is the **dev-time policy**: it is what the browser enforces under `vite dev`, and the entire `local` Playwright suite continues to run under it. The inline-script `sha256` in `client/index.html` stays valid and stays unit-tested — it guards the dev policy against snippet drift.

In production the Worker removes this `<meta>` before the browser parses it and substitutes the header. No `<meta>` CSP is ever enforced in production; no double policy.

`scripts/generate-legal.mjs` is unchanged — it keeps copying the templates (including their `<meta>`) through to `client/public/{privacy,terms}.html`.

## Part 4 — `client/public/_headers`

Remove the `Content-Security-Policy:` line. Keep everything else:

```
/*
  X-Frame-Options: DENY
  X-Content-Type-Options: nosniff
  Referrer-Policy: strict-origin-when-cross-origin
  Permissions-Policy: camera=(), microphone=(), geolocation=(), browsing-topics=()
  Cross-Origin-Opener-Policy: same-origin
```

Rationale: the Worker now sets the CSP on every HTML response; a CSP header on non-HTML assets does nothing. Keeping it in `_headers` would create a second, nonce-less policy on the shell (until the Worker overwrites it) and pure noise on `.js`/`.css` — cleaner to have one owner.

### Manual / post-deploy — the JSD check (documented, run once after merge)

JSD runs only at Cloudflare's edge. After the merge auto-deploys:

1. Load `https://editor.danplace.tech/` in a real browser, DevTools console open, hard reload.
2. **Expect zero CSP violations.**
3. Network tab: `/cdn-cgi/challenge-platform/scripts/jsd/main.js` returns 200 and executes (no "Refused to execute" for its inline bootstrap).
4. View source: the injected JSD `<script>` tags carry `nonce="…"` matching the `Content-Security-Policy` response header.
5. Repeat on `/privacy`.

If Cloudflare does **not** stamp the nonce onto its injected scripts (contradicting its docs), the JSD inline violation returns. Fallback, no further code: accept the single violation and document it in `ROADMAP.md` — the blocked script is Cloudflare bot telemetry only and does not affect the app (verified: editor loads and runs with it blocked). The nonce-header migration still stands on its own as cleaner CSP delivery.

## Open risks

1. **Cloudflare not honouring a Worker-set CSP header for JSD nonce injection.** The docs say it parses "your CSP response header"; a Worker-set header is that. Unverifiable pre-merge. Mitigation: Part 5's post-deploy check; documented fallback (accept the one violation) needs no code.
2. **`Cache-Control: no-store` on the HTML shell.** Slightly more origin fetches for the small HTML document (not assets). Negligible at this traffic level; it is the correct setting for a nonce CSP.
3. **`HTMLRewriter` overhead per HTML request.** One streaming pass over a ~20 KB shell, two element handlers. Sub-millisecond; HTML requests are a small fraction of traffic (assets dominate and skip the transform).
4. **A future third inline script added without a nonce** would be blocked in production. That is the CSP working as intended; today there is exactly one inline script and the transform nonces it automatically.
5. **`wrangler dev` not applying `_headers`.** Already relied on by v1.60.2's collab header assertion and confirmed working; unchanged here.
