# Local E2E Suite in CI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Run the existing `e2e/local/*.spec.ts` Playwright suite as a required GitHub Actions check on every push/PR to `master`, alongside the existing unit-test job.

**Architecture:** A new `e2e` job in `.github/workflows/test.yml`, parallel to the existing `test` job, installs Chromium and runs `npm run test:e2e:local`. `playwright.config.ts` gains CI-aware retries and failure-artifact capture (trace + screenshot) so a CI-only failure is debuggable without reproducing it locally.

**Tech Stack:** GitHub Actions, `@playwright/test` (already a devDependency), the existing `e2e/local/*` spec files (unmodified).

**Spec:** `docs/superpowers/specs/2026-08-19-e2e-ci-local-design.md`

## Global Constraints

- `e2e` job triggers: same as the existing `test` job — `push` to `master`, `pull_request` targeting `master`. (Spec Goals.)
- `e2e` runs in parallel with `test` — no `needs:`. (Spec Goals, Architecture.)
- `retries: process.env.CI ? 2 : 0` in `playwright.config.ts` — zero locally, up to 2 in CI. (Spec Goals, Architecture.)
- `trace: "on-first-retry"` and `screenshot: "only-on-failure"` in the `use` block. (Spec Goals, Architecture.)
- On failure, upload `playwright-report/` via `actions/upload-artifact@v4`, `retention-days: 7`. (Spec Goals, Architecture.)
- The `Pass Tests` ruleset (`required_status_checks`) is **not** touched by this plan — adding `e2e` as required is an explicit manual follow-up after this merges and reports green at least once. (Spec Architecture: "Ruleset update", Error handling.)
- No change to the `test` job's own steps or triggers. (Spec Non-goals.)
- No browser-binary caching, no cross-browser coverage, no sharding. (Spec Non-goals.)

- [ ] **Step 1: Add CI-aware settings to `playwright.config.ts`**

Open `playwright.config.ts`. It currently looks like this:

```typescript
import { defineConfig, devices } from "@playwright/test";

export default defineConfig({
  testDir: "./e2e",
  fullyParallel: true,
  retries: 0,
  reporter: "list",
  use: {
    ...devices["Desktop Chrome"],
  },
  webServer: {
    command: "vite dev --config client/vite.config.ts --port 5275",
    url: "http://localhost:5275",
    reuseExistingServer: !process.env.CI,
  },
  projects: [
    {
      name: "local",
      testDir: "./e2e/local",
      use: { baseURL: "http://localhost:5275" },
    },
    {
      name: "collab",
      testDir: "./e2e/collab",
      use: { baseURL: "http://localhost:8787" },
    },
  ],
});
```

Change `retries: 0` to `retries: process.env.CI ? 2 : 0`, and add
`trace`/`screenshot` to the `use` block:

```typescript
import { defineConfig, devices } from "@playwright/test";

export default defineConfig({
  testDir: "./e2e",
  fullyParallel: true,
  // Zero retries locally (a real failure should fail fast); up to 2
  // attempts in CI before a test counts as failed, absorbing one-off
  // timing flakiness on GitHub Actions' shared runners without masking
  // a genuinely broken test (it still fails the required check if all
  // 3 attempts fail).
  retries: process.env.CI ? 2 : 0,
  reporter: "list",
  use: {
    ...devices["Desktop Chrome"],
    // Captured starting from the first retry of anything that failed
    // once — exactly the run whose failure needs debugging. No tracing
    // overhead on a first-attempt pass, the common case.
    trace: "on-first-retry",
    // Cheap, always useful at the moment of failure, independent of
    // whether retries are enabled.
    screenshot: "only-on-failure",
  },
  webServer: {
    command: "vite dev --config client/vite.config.ts --port 5275",
    url: "http://localhost:5275",
    reuseExistingServer: !process.env.CI,
  },
  projects: [
    {
      name: "local",
      testDir: "./e2e/local",
      use: { baseURL: "http://localhost:5275" },
    },
    {
      name: "collab",
      testDir: "./e2e/collab",
      use: { baseURL: "http://localhost:8787" },
    },
  ],
});
```

- [ ] **Step 3: Add the `e2e` job to `.github/workflows/test.yml`**

Open `.github/workflows/test.yml`. It currently looks like this:

```yaml
name: Test

on:
  push:
    branches:
      - master
  pull_request:
    branches:
      - master

jobs:
  test:
    runs-on: ubuntu-latest

    steps:
      - name: Checkout repository
        uses: actions/checkout@v7

      - name: Setup Node.js
        uses: actions/setup-node@v7
        with:
          node-version: 'lts/*'
          cache: 'npm'

      - name: Install dependencies
        run: npm ci

      - name: Run tests
        run: npm test
```

Add a second job, `e2e`, after `test`:

```yaml
name: Test

on:
  push:
    branches:
      - master
  pull_request:
    branches:
      - master

jobs:
  test:
    runs-on: ubuntu-latest

    steps:
      - name: Checkout repository
        uses: actions/checkout@v7

      - name: Setup Node.js
        uses: actions/setup-node@v7
        with:
          node-version: 'lts/*'
          cache: 'npm'

      - name: Install dependencies
        run: npm ci

      - name: Run tests
        run: npm test

  e2e:
    runs-on: ubuntu-latest

    steps:
      - name: Checkout repository
        uses: actions/checkout@v7

      - name: Setup Node.js
        uses: actions/setup-node@v7
        with:
          node-version: 'lts/*'
          cache: 'npm'

      - name: Install dependencies
        run: npm ci

      - name: Install Playwright browser
        run: npx playwright install --with-deps chromium

      - name: Run local e2e suite
        run: npm run test:e2e:local

      - name: Upload Playwright report
        if: failure()
        uses: actions/upload-artifact@v4
        with:
          name: playwright-report
          path: playwright-report/
          retention-days: 7
```

`e2e` has no `needs:` — it starts immediately, in parallel with `test`,
same triggers (`push` to `master`, `pull_request` targeting `master`)
inherited from the workflow-level `on:` block above both jobs.

- [ ] **Step 7: Verify the failure path once, deliberately**

On the same branch, temporarily break one assertion so the suite fails
on purpose — for example, in `e2e/local/documents.spec.ts`, change:

```typescript
  expect(docsInStorage[0].id).toBe(docId);
```

to:

```typescript
  expect(docsInStorage[0].id).toBe(docId + "-deliberately-wrong");
```

Commit this as a throwaway commit, push, and let CI run:

```bash
git add e2e/local/documents.spec.ts
git commit -m "test: deliberately break an assertion to verify the e2e CI failure path"
git push
gh pr checks <pr-number> --watch
```

Expected: the `e2e` check goes red. Open the failed run's Summary page
(`gh run view <run-id> --web` or the Actions tab) and confirm a
`playwright-report` artifact is attached and downloadable.

Then revert the deliberate breakage:

```bash
git revert HEAD --no-edit
git push
gh pr checks <pr-number> --watch
```

Expected: `e2e` goes green again, confirming the revert restored the
original passing assertion and the CI failure path itself worked
end-to-end (red check + artifact) before merging anything real.
